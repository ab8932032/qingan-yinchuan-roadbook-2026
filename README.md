# 青甘银川 · 2026 自驾路书（Web）

手机友好的单页 HTML 路书，也是一册会在旅途中继续生长的小杂志。它既要把每天几点出发、在哪里停、住在哪里说清楚，也要让多年以后重新翻开时，仍能读见一处地方的来历、气味和当时的感受。

## 路书风格

### 一句话定义

**西北公路杂志 × 旧纸旅行手账。** 页面以真实风景影像、克制的文学感和清楚的行程信息共同叙事：远看像一本有光线变化的旅行杂志，近看仍是一份可以在路上迅速执行的路书。

风格关键词：**旷野、风沙、纸感、暮色、湖光、安静、克制、可执行**。视觉不走明亮活泼的打卡攻略风，也不做厚重仿古；所谓“文艺”来自留白、准确的文字、真实照片和缓慢的节奏。

### 色彩系统

颜色取自沙丘、落日、湖水、墨色与旧纸。暖色负责旅程前半段和主要行动，冷色负责地图、链接、天气及青海湖一带的空间转场。

| 角色 | CSS 变量 / 色值 | 使用方式 |
|---|---|---|
| 沙金 | `--sand: #c4a574` | 分隔线、序号、弱强调、路线连接 |
| 浅沙 | `--sand-light: #e8d5b5` | 次级按钮、暖色渐变、柔和底色 |
| 暮橙 | `--dusk: #c45c26` | 主按钮、当前状态、重点数字和提醒 |
| 墨黑 | `--ink: #1a1410` | 正文、深色舞台、图片遮罩底色 |
| 软墨 | `--ink-soft: #3d342c` | 说明文字、元信息、次级标题 |
| 旧纸 | `--paper: #f3efe6` | 页面主背景 |
| 深纸 | `--paper-2: #e8e2d4` | 卡片渐变、表头、占位背景 |
| 湖青 | `--lake: #2a6f7f` | 链接、地图、天气、冷色按钮 |
| 夜蓝 | `--night: #1e2438` | 夜晚、青海湖和旅程收束段落 |
| 松绿 | `--ok: #3d6b4f` | 安全、完成、适宜状态 |
| 警棕 | `--warn: #a65d2e` | 风险、异常和需留意信息 |

使用原则：一个界面只设一个暮橙主操作；湖青用于信息型操作，不与暮橙争夺主次。大面积背景保持低饱和，状态色尽量以浅色透明底呈现。避免纯白大底、亮蓝链接、霓虹色和高饱和多色标签。

### 字体与文字层级

- 标题、路线地名、引文和带情绪的短句使用 `ZCOOL XiaoWei`；字重保持 `400`，依靠字号、留白和少量字距建立层级，不使用粗黑标题。
- 正文、按钮、表格和功能信息使用 `Noto Sans SC`，回退为 `system-ui, sans-serif`；常用字重为 `400 / 500 / 700`。
- 正文基准行高为 `1.65`。正文通常为 `14–15px`，辅助信息为 `9–12px`；移动端首屏标题使用 `clamp(2.2rem, 9vw, 3.2rem)`，章节标题约 `1.75rem`。
- 英文眉题或日期可使用 `0.14–0.18em` 字距，中文长段落不拉宽字距。短引文可以偏诗意，功能文案必须直接。
- 信息层级顺序为：章节眉题 → 宋体主标题 → 一句引文或引导 → 正文/卡片 → 标签与元信息。

### 版式与空间

- **移动端优先**：正文阅读栏最大宽度为 `720px`，居中显示，左右内边距 `16px`；章节通常使用 `36px 0 8px` 的纵向间距。
- 首屏使用接近满屏的风景图（`92dvh`），文字贴近底部排布，并用由浅到深的黑色渐变保证可读性。
- 内容沿单一纵向阅读流推进，不用后台式侧栏。底部固定导航高度为 `56px`，同时兼容 `safe-area-inset-bottom`。
- 基础卡片圆角为 `18px`，常用阴影为 `0 12px 40px rgba(26, 20, 16, 0.12)`；边框采用低透明沙金。卡片应像贴在纸上的记录，不做悬浮玻璃面板。
- 背景不是纯色：旧纸底上叠加极淡纤维、噪点和低透明径向光晕。宽屏仅在两侧增加“左暖沙、右湖青”的环境色，中间阅读区保持干净。
- 章节色温随路线推进：银川与河西偏暖沙/暮橙，柴达木偏灰冷，青海湖与夜晚偏湖青/夜蓝，形成从暖到冷再归于旧纸色的旅程节奏。

### 核心组件语言

- **Hero**：大幅真实风景 + 深色渐变 + 宋体标题 + 一句短引文；标签使用半透明白色胶囊。
- **按钮**：统一胶囊形。暮橙为主操作，湖青渐变用于地图，浅沙为普通操作，透明白描边只用于深色图片上。
- **日程卡片**：以日期、地点和当日一句话为摘要，展开后呈现时间、路线、住宿与补记；封面影像应比文字更早建立当天情绪。
- **路线节点**：短地名配圆形序号，以沙金连接；窄屏改为可换行的小胶囊，不强迫横向滚动。
- **地点舞台**：使用接近黑色的全宽背景和大幅影像，让“风里的站”成为杂志式的沉浸章节；说明文字保持米白，操作按钮降低存在感。
- **标签与提醒**：标签只表达少量必要状态；普通信息用纸灰，重点用暮橙，安全用松绿。提醒采用左侧色线与浅透明底，不使用大面积警示红。
- **地图、天气、预算、清单**：视觉服从功能。仍沿用纸色、宋体小标题和低饱和状态色，但优先保证数字、时间、风险和操作清晰。

### 影像规则

- 优先使用有地貌尺度、道路方向、天气和自然光线的真实照片；少用过度调色、拼贴、插画化滤镜和通用旅游海报图。
- 色调以沙金、土褐、低饱和青蓝和深墨为主。照片可以有人，但人物不应长期占据画面中心，重点始终是“人在辽阔地貌中的尺度”。
- 每天保留一张主图，其余影像进入对应地点；连续图片之间穿插文字、路线或实用信息，保持旅行杂志的呼吸感。
- 照片使用 `cover` 裁切并保留明确焦点；视频提供静态封面。加载失败时回落为深纸色与浅沙渐变，避免突兀的浏览器破图标。
- 当前网络图片只是版式占位，最终以旅途中自己拍摄的照片、Live Photo 和短视频替换。

### 动效与交互

- 动效整体是“慢呼吸、轻进入”：首屏照片以 `18s` 缓慢缩放，普通照片使用更小幅度的呼吸效果；视频和 Live Photo 不叠加缩放动画。
- 首屏文字依次淡入上移，内容进入视口时只移动约 `14–18px`；按钮在可悬停设备上仅上移 `1px` 并增加轻阴影。
- 日程展开使用短距离位移，不用大幅弹性、旋转或强烈视差。页面顶部用 `3px` 沙金至暮橙渐变显示阅读进度。
- 所有主要功能均可触摸操作，不把信息只藏在 hover 中。尊重 `prefers-reduced-motion`：关闭呼吸、平滑滚动、淡入和非必要过渡。

### 响应式与可访问性

- `560px` 以下压缩路线、时间线和部分网格；`680–720px` 以上再展开多列信息；`1100px` 以上只增强页面侧缘氛围，不无限拉宽正文。
- 适配刘海屏底部安全区；图片保留 `alt`，纯氛围图可使用空 `alt`。深色图片上的正文必须有足够遮罩，不依赖照片本身的明暗碰运气。
- 可点击元素保持足够触摸面积和明显焦点态；颜色之外还应有文字、图标或结构说明状态。
- 打印时移除导航、动效、进度条、灯箱及装饰背景，卡片避免跨页断裂，输出回归清楚的白底路书。

### 新增内容时的自检

1. 这部分是在讲旅程，还是像旅游平台在堆服务项目？
2. 主操作是否只有一个，暮橙与湖青的职责是否清楚？
3. 标题是否克制、正文是否直接，宋体有没有被滥用于长篇功能信息？
4. 照片是否提供地点、光线或尺度信息，而不只是“好看”？
5. 卡片、圆角、阴影和标签是否比现有组件更抢眼？如果是，应收敛。
6. 手机单手阅读、弱网图片失败、减少动态效果和打印场景是否仍然可用？

## 这本路书的编辑原则

这不是景区服务目录，也不是项目汇报。修改任何一处文字时，都要顺带检查全篇是否仍然保持同一种声音；用户举出的地点只是例子，不应只修例子本身。

- 每个重要地点至少回答四件事：眼前会看见什么；它为何在地质、历史或文化上独特；它与本次路线怎样衔接、最适合怎样体验；有哪些真正影响行程的时间、预约和安全信息。
- 先写成自然、连贯、可阅读的段落，再安放实用信息。票价、班车、项目和服务只保留与本次行程有关的部分，并在叙述中说明取舍，不把所有选项罗列成说明书。
- 文艺感来自准确的观察和具体细节，不靠故作深沉。风、光线、材质、尺度与人的感受可以写；“把一切交给风景”“收住日落”“给身体留白”一类套话不用。
- 正文不使用公司汇报式的小标题，例如“背景与说法”“今日节奏”“实际节奏”“主场”“取舍”“关键路段”；也避免把“怎么玩、怎么拍、怎么吃”直接当作段落标题。
- 日期与地点旁的短说明也要像人说话：直接写几点出发、几点抵达、做什么和住哪里，不使用“上午轻线”“中午收束”“主线／支线”“重点停靠”一类只有编辑者看得懂的速记。
- 成品只写最终采用的路线，不记录讨论过程。已经删掉的地点、曾经考虑过的替代路线和“保留／取消／不纳入”等取舍说明都不应出现在正文里；只写当天实际经过哪里、怎样行驶和在哪里住宿。
- “即可、就好、就够、只需、无需、不必”等公文化句式连续出现时必须改写。安全、闭园、预约和驾驶信息则应直接、清楚，不为追求文艺而含糊。
- 不把每个地方都写成同一种模板。景点需要背景与体验；补给城市可以简洁；危险路段以安全为主。内容厚度取决于它在旅程中的意义。
- 有关 9.25 只写成“某人的纪念日”或相近的含蓄表达，不出现生日、惊喜等字眼。
- 所有事实尽量以景区、政府、研究机构等可靠来源核对，但引用和免责声明不能淹没正文。时间、票价和开放状态仍以出发前的当年公告为准。
- 现有网络图片都是版式占位，之后统一换成旅途中自己拍摄的静态照片、Live Photo 和视频；新增内容时要为这些影像留下自然的位置。

## 天气说明

- 天气不再按银川、海西州、共和县等大行政区粗略显示，而是按贺兰山宿集、平山湖、七彩丹霞、敦煌雅丹、黑独山、水上雅丹、翡翠湖和青海湖东岸等实际游玩坐标分别查询。
- 页面使用 Open-Meteo 坐标预报（CC BY 4.0）：默认读取未来 16 天，并对齐到路书计划的日期与大致游玩时刻；7 天内作为短期预报，8–16 天只标为趋势。
- 行程尚未进入预报范围时，卡片会写明预计开放日期，并仅把该地点“此刻”的温度、体感与阵风作为地形差异参考，不冒充 9 月底的远期预报。
- 手机天气 App 无法直接搜景点时，可用附近县镇兜底：黑独山查冷湖镇、翡翠湖查大柴旦、敦煌景点查敦煌市、张掖景点查张掖市／临泽县；青海湖应按实际岸线选择共和县或刚察县。
- 预报每 30 分钟检查更新一次并在本机缓存；临行仍以出发前 3–5 天逐小时预报、景区公告和现场风力为准。

## 后续加入旅途影像

- 照片可直接替换日程卡片或景点卡片中的 `<img>` 地址，现有大图灯箱会自动沿用。
- 视频可放进同一个 `.day-cover` 或 `.spot-img` 容器，使用 `<video controls playsinline preload="metadata" poster="封面图地址">`；页面已预留与照片一致的比例、底色和移动端播放样式。
- 建议每一天只留一张主图，其余素材放在对应景点卡片中；照片与短视频穿插会比连续堆叠更像一本旅途影集。
- 每个日期展开后都有“途中补记”，可以写下当天的一句话、临时改变的路线，并直接加入照片或视频。文字使用本地存储，媒体使用浏览器 IndexedDB；两者都只存在当前设备。清理浏览器数据或更换设备前，应先把重要内容另行备份。

### 统一媒体格式

所有正式素材使用同一套 `data-media` 规则：

```html
<!-- 静态照片：自动使用缓慢呼吸效果 -->
<div class="day-cover" data-media="photo" data-caption="9.28 · 平山湖">
  <img src="assets/2026-09-28-pingshanhu.jpg" alt="平山湖大峡谷" />
</div>

<!-- Live Photo：使用关联的 MOV/MP4，poster 是静态封面；自动静音循环 -->
<div class="day-cover" data-media="live" data-caption="风穿过峡谷">
  <video src="assets/2026-09-28-live.mov" poster="assets/2026-09-28-live.jpg" muted loop autoplay playsinline controls></video>
</div>

<!-- 普通视频：不使用呼吸效果，显示原生播放控件 -->
<div class="day-cover" data-media="video" data-caption="去往丹霞的路上">
  <video src="assets/2026-09-28-road.mp4" poster="assets/2026-09-28-road-cover.jpg" playsinline controls preload="metadata"></video>
</div>
```

“风里的站”背景也使用相同规则：照片保留 `data-full="图片地址"`；视频或 Live Photo 在对应 `.spot-slide` 上填写 `data-media="video"` 或 `data-media="live"`、`data-video="视频地址"`，并可用 `data-poster="封面地址"`。切换到视频时，照片呼吸动画会自动停止。
