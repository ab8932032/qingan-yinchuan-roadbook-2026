# 路书正向叙述设计

## 目标

整本路书只告诉读者推荐做什么、什么时候做、满足什么条件时做，以及下一步去哪里。行程建议、景点背景、安全提醒和系统提示都直接给出正向信息，全文去除先写否定对象、再解释正确做法的反向表达。

## 覆盖范围

- `index.html` 中全部用户可见文字：总览、逐日路线、附近可选地点、风里的站、地图、天气、预算、住宿、清单与运行时生成文案。
- `README.md` 中面向后续编辑者的视觉与写作规则。
- HTML 属性里会被辅助技术读出的 `aria-label`、图片说明和交互提示。

代码注释、条件判断、错误处理和第三方接口字段属于程序实现，不参与旅行文案改写。

## 叙述规则

### 行程安排

每句话从推荐动作开始：直接前往、优先安排、抵达后先、达到某个时间条件时进入、把某段时间留给某处、在正规区域完成某项活动。

被排除的地点不写成劝退。例如“当天不建议去茶卡”改为“当天把傍晚留给青海湖；茶卡适合另排半天”。读者看到的是当前推荐路线和未来适合的安排，而不是被否定的选择。

### 安全提醒

安全信息保留完整，并改成可执行动作：

- “不要在公路停车”改为“车辆驶入正规停车区后再拍照”。
- “司机不喝酒”改为“司机全程保持零酒精”。
- “不要穿过私人牧场”改为“沿公开入口和开放岸线进入湖边”。

### 地质、历史与文化说明

直接陈述构成、来源和变化过程。用“翡翠湖由盐业采坑与盐池组成”替代“翡翠湖不是天然整湖”；用“雅丹先在旱地形成，河流改道后被湖水包围”替代“它并非在水下长成”。

### 状态与系统提示

动态状态写明当前可用信息和下一步：

- 天气窗口尚远时，显示“当前展示地点实况；行程预报将在进入未来 16 天后出现”。
- 地图详细道路加载不足时，显示“完整行程底线已显示；已载入 X/Y 个日期的详细道路”。
- 图片加载异常时使用视觉回退，用户文案只说明当前可执行入口。

## 词语检查

对用户可见文本扫描“不、别、无、未、避免、禁止、取消、失败、跳过”等反向词。每一处都按语义改写，禁止机械删字或批量替换。

允许保留的仅限专有名词或客观字段值；出现时必须逐项人工确认。代码注释和程序逻辑不计入文案验收。

## 交互与结构

本次只改文字，不改变主路线、景点数据、地图算法、卡片结构、折叠方式和视觉布局。附近可选地点仍保留时间成本与条件，但标签改成正向分类，例如“适合另排半天”“时间宽裕时加入”“顺路短停”。

## 验收方式

1. 自动提取 HTML 中用户可见文本与动态字符串，扫描反向词并输出命中位置。
2. 人工逐项核对命中，确认专有名词和必要状态之外已经清零。
3. 抽查每天摘要、附近可选地点、风里的站、天气与地图提示，确认每句话都能回答“推荐做什么”。
4. 运行现有路书验收脚本、HTML 解析与页面浏览器检查，确认文字改写没有破坏结构和交互。
